# Gateway 0.1.6 – ruční E2E test OTA

Připraveno 2026-09-29 jako lokální podepsané vydání. Balíček nebyl publikovaný
na server a nebyl vytvořen žádný rollout. Server ani testovací VM se nezměnily.

## Změna a ověření

Oproti 0.1.5 se mění pouze vestavěné číslo verze na **0.1.6**. Aplikační kód
zůstává stejný; vydání umožňuje otestovat skutečný upgrade a potvrzení nové verze.

- Zdrojový commit: `1fdc9af74ecda0fe07329ca6141378f2d3cddfce`.
- Platforma: `linux-arm64`, launcher protokol 2.
- Klíč: `virtualbox-lab-20260929`, již zavedený na serveru i testovací VM.
- Velikost binárky: 20 770 430 bajtů.
- SHA-256 binárky: `687ee78c9bc0b712713bcc94ea431026c9c37509e7174e33e8ad5e386ed21789`.
- Ověřený podpis, hash a velikost manifestu vůči binárce.
- V jednorázovém ARM64 kontejneru bez sítě prošel skutečný přechod launcheru
  z 0.1.5 na 0.1.6: `active=0.1.6`, `previous=0.1.5`, `trial=false`.
  Agent potvrdil správnou verzi a otevřel lokální služby. Kontejner byl odstraněný.

Lokální ověření nenahrazuje E2E test WSS příkazu a restartu testovací VM.

## Soubory pro publikování

Složka `dist/releases/0.1.6/` obsahuje:

| Soubor | Použití |
|---|---|
| `manifest.json` | Pole „Podepsaný manifest“ |
| `gateway` | Pole „Binární soubor gateway“ |
| `SHA256SUMS` | Kontrolní součty souborů |
| `public-keys.json` | Veřejný klíč pro ověření; na serveru a VM už je zavedený |
| `README.md` | Kopie tohoto postupu |

Do formuláře se nahrávají pouze `manifest.json` a `gateway`. Balíček neobsahuje
privátní podpisový klíč, cloudový token ani konfiguraci VM.

## Ruční E2E postup

1. Jako SUPERADMIN otevři [Tiskové brány](https://cloud.stitkovac.app/gateways)
   a část **Aktualizace bran → Publikovat podepsané vydání**.
2. Vyber `manifest.json` a `gateway` ze složky výše a klikni **Publikovat vydání**.
   Tím se uloží balíček; brána se ještě neaktualizuje.
3. Vyber cílovou verzi **0.1.6**, akci **Aktualizovat** a pouze testovací VM.
   Nastav servisní okno například od příští minuty na 30 minut.
4. Klikni **Naplánovat nasazení** a potvrď vybranou bránu i verzi.
5. Sleduj stav konkrétní brány a **Zobrazit audit**. Úspěšný konečný stav je
   **Verze potvrzena** (`SUCCEEDED`) s běžící verzí **0.1.6**.
6. Obnov [lokální administraci](https://127.0.0.1:8443): nahoře musí být
   **Verze 0.1.6**, připojení k serveru a původní DHCP rezervace tiskárny.
   Vyzkoušej tisk z aplikace/serveru na simulovanou tiskárnu přiřazenou této bráně.

Pro samostatný test návratu poté vyber **0.1.5** a akci
**Vrátit předchozí vydání** pro stejnou bránu. Tato verze už je publikovaná
na serveru a po úspěšném upgradu bude uložená jako předchozí na bráně.
