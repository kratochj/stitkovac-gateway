# Verze 0.1.7 – připravený upgrade agenta a laboratoře

Připraveno 2026-09-29. Nic nebylo publikované na server ani nainstalované do VM.

## Která část obsahuje opravu

Živý přehled na portu **9443** poskytuje samostatný program `gateway-lab`.
Opravu proto obsahuje **laboratoř 0.1.7**, nikoli samotný OTA agent.

Současný OTA kanál aktualizuje pouze agenta. Podepsaný **agent 0.1.7** je
připravený pro ruční E2E upgrade, ale jeho nahrání nezmění web laboratoře.
Oproti agentovi 0.1.6 se mění pouze číslo verze.

## 1. Upgrade laboratoře s opravou živých dat

Ve složce `dist/releases/0.1.7/` je připravený spouštěč
**`Upgrade-laboratore.command`**. Spusť ho ručně dvojklikem nebo z Terminálu.
Používá tento checkout, jeho Ansible inventory a již uložený SSH klíč testovací VM.
Vyžaduje Python 3.11+, Ansible a spuštěnou VM dostupnou na lokálním portu 2222.

Stejný krok z kořene repozitáře:

```sh
python3 scripts/virtualbox/upgrade-lab.py 0.1.7
```

Nejprve dokonči běžící tisky a OTA nasazení. Tento servisní upgrade krátce
zastaví agenta, místní testovací server i simulovanou tiskárnu. Vymění pouze
`gateway-lab`, obnoví read-only root a znovu spustí původní služby.
Nemění server, token, heslo, tiskový journal, DHCP rezervace ani výběr OTA verze.
Při chybě samotné instalace obnovuje předchozí binárku. Selhání následného
zdravotního testu pouze nahlásí; nejde o automatický OTA rollback launcheru.

Po dokončení ručně obnov `https://127.0.0.1:9443/`. Nahoře musí být
**Verze laboratoře 0.1.7** a živé připojení. Tisk z cloudového serveru se objeví
v **Dokumenty přijaté tiskárnou** s časem a velikostí. Staré místní testovací
úlohy zůstanou oddělené pod vlastním nadpisem.

Pouhá lokální kontrola balíčku, bez spojení s VM:

```sh
python3 scripts/virtualbox/upgrade-lab.py 0.1.7 --verify-only
```

## 2. OTA upgrade agenta na 0.1.7

V [administraci serveru](https://cloud.stitkovac.app/gateways) jako SUPERADMIN
otevři **Aktualizace bran → Publikovat podepsané vydání** a vyber:

| Pole | Soubor z `dist/releases/0.1.7/` |
|---|---|
| Podepsaný manifest | `manifest.json` |
| Binární soubor gateway | `gateway` |

Publikuj vydání. Pak vyber **0.1.7**, **Aktualizovat**, pouze testovací bránu
a servisní okno. Potvrď nasazení a sleduj výsledek **Verze potvrzena**.
Na portu 8443 se po aktualizaci zobrazí **Verze 0.1.7**.

Soubor `lab/gateway-lab` do OTA formuláře nepatří. Pro test návratu vyber
předchozí vydání skutečně uchované na dané bráně a akci **Vrátit předchozí vydání**.
Nespouštěj servisní upgrade laboratoře a OTA agenta současně.

## Artefakty a ověření

Zdrojový commit obou binárek: `251e7bbb9fe17272df9dffe42f25f277cd3875ad`.
Obě jsou Linux ARM64. Balíček obsahuje pouze veřejné klíče; nejsou v něm
přístupové údaje, konfigurace zákazníka ani privátní podpisový klíč.

| Artefakt | Velikost | SHA-256 |
|---|---:|---|
| `gateway` | 20 770 430 B | `45464fbbe16d619e862422fd5a4a9308f6654b2e0396dfa458b3f5c85c4a62a5` |
| `lab/gateway-lab` | 19 434 905 B | `c41ed1077fc76ea91a1796f20de2590a5453cdb15a605c997846932705d71497` |

Agent má Ed25519 podpis zavedeným pilotním klíčem `virtualbox-lab-20260929`,
launcher protokol 2. Laboratoř se instaluje servisně z lokálního balíčku
s kontrolou SHA-256; není součástí podepsaného OTA manifestu agenta.

Ověřeno:

- Lab regresní testy s race detectorem, Go vet a sestavení obou ARM64 binárek.
- Syntaxe Ansible playbooku a Python spouštěče, lokální checksum balíčku.
- Obě binárky skutečně hlásí 0.1.7 při spuštění v ARM64 kontejneru bez sítě.
- Podepsaný přechod launcheru 0.1.6 → 0.1.7, potvrzená verze a uchovaná 0.1.6.
- Živé TCP/SSE chování, offline/reconnect a mobilní přehled prošly prohlížečovým
  testem v předchozím commitu opravy.

Servisní playbook se na běžící VM zatím nespouštěl. Je připravený k tvému
ručnímu spuštění; nejde o tvrzení, že už byla VM aktualizovaná.
